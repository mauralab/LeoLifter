# LeoLifter Web

Responsive public landing page for the planned workout-program web application. No login, registration, Telegram SDK, database calls or tracking is enabled.

## Run

```sh
npm install
npm run dev
```

Open http://localhost:3000. `/` redirects to `/en`.

## Languages

Localized, server-rendered routes: `/en` (English), `/uk` (Ukrainian), `/nb` (Norwegian Bokmål), `/de` (German), `/pl` (Polish). The header language picker navigates between them; the selected language is kept in the URL and survives refresh/sharing. Each page has the corresponding HTML language and metadata. Unknown locale paths return 404.

Translations live in `lib/i18n/messages/`, with a shared dictionary shape checked by TypeScript. Add new keys to every dictionary. Norwegian currently means Bokmål; Nynorsk can be added separately if needed. Translation copy should receive native-speaker review before public launch.

## Page structure

- `app/[locale]/layout.tsx`: localized document, metadata and static locale generation.
- `app/[locale]/page.tsx`: localized landing route.
- `components/landing/landing-page.tsx`: responsive introduction, local sample-workout interaction, platform vision and roadmap.
- `app/globals.css`: existing shadcn tokens plus scoped landing styles.
- `public/brand/leo-web.png`: original LeoWeb mascot used by the header/footer wordmark.
- `app/favicon.ico`: supplied Leo.ico browser-tab icon, automatically registered by Next.js.

The workout preview is sample data only. Day selection, exercise completion and reset work locally; refreshing resets the preview. All calls to action navigate to real page sections. Future capabilities are described as plans rather than presented as working account/program features. The header includes a light/dark toggle. It follows the system preference initially, saves an explicit choice locally, and keeps it across reloads and language changes. Flags accompany every language (UK for English); SVG artwork renders independently of operating-system emoji support. On narrow screens the trigger shows its flag while language names remain visible inside the keyboard-accessible menu.

## Future application direction

Users should be able to create and follow workout programs from the browser and a Telegram Mini App. Keep shared responsive components and locale dictionaries reusable by both entry points. The future Telegram bot and Telegram-linked authentication are not implemented here. Use an internal user ID with a linked Telegram ID; future Mini App identity must be verified server-side before creating/linking accounts. Never treat a client-supplied Telegram ID as proof of identity. Backend ownership and auth/schema integration remain separate implementation tasks.

## Checks

```sh
npm run lint
npm run typecheck
npm run build
```

When routes change, regenerate Next.js types with `npx next typegen`. Old `.next/dev/types` files from a previous route tree may need to be regenerated by restarting development mode.

## Theme initialization

The theme provider uses a browser preference store rather than rendering an inline script. `public/theme-init.js` is an external async React script resource loaded by the localized root layout. It applies the same saved/system preference before hydration when available; the provider also initializes it after hydration and observes system and cross-tab preference changes. Keep the bootstrap logic aligned with the provider. This avoids React development warnings from inline scripts during client layout mounts.
